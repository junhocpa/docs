# 택스봇 수임고객정보 → Airtable 동기화

## 대상

- 입력: 택스봇 수임고객정보 엑셀 2개
  - **수임처등록정보** (1행 제목, 5행 헤더 39컬럼, 6행부터 데이터)
  - **연락처정보** (1행 제목, 4행 헤더 14컬럼 — 3번째 컬럼은 헤더 공란이지만 홈택스부서사용자ID, 5행부터 데이터)
- 출력: Airtable 베이스 `apprWMoKzGUuIuNdW` (솔루션택스 업무관리)의 4개 테이블
- 비밀번호(홈택스ID/PW, 주민등록번호 포함)는 **그대로 저장**한다 (대표 결정 사항 — 제외하거나 별도 보관 권유 금지)

## 테이블·필드 ID

`references/ids.md` 참조. 핵심:

| 테이블 | ID | 쓰기 방식 |
|---|---|---|
| 거래처 (마스터) | `tblM3ud4wVMVQlc2c` | 신규는 create, 기존은 record id로 update |
| 소스_택스봇 | `tbl7tkjO8cKsHm0Sz` | 사업자번호 `fldalu48zlznSBqM4` upsert (사업자번호 없는 개인은 create) |
| 소스_택스봇_연락처 | `tbliolNHdLfhGpoD7` | 항목명(`성명 — 거래처명`) upsert 또는 create |
| 접속정보 | `tblSVIJn4Dixg1nEn` | 항목명(`홈택스 — 마스터상호`)으로 기존 조회 후 create/update |

## 절차

1. **기존 데이터 조회** (ToolSearch로 Airtable 도구 로드 후):
   - 마스터 전체 → `existing_masters.json` (id·사업자번호·거래처코드·소스·상호·대표자·담당자·연락처·이메일·구분·수임일·상태)
   - 접속정보 전체 → `existing_access.json` (id·항목명·사이트·계정ID·비밀번호·수임동의)
   - 결과가 커서 파일로 저장되면 `cellValuesByFieldId` 구조를 Python으로 파싱한다.
2. **변환**: `python3 scripts/transform.py <수임처등록정보.xlsx> <연락처정보.xlsx> <existing_masters.json> <출력폴더>`
   → `master_new.json`, `master_update.json`, `report_phase1.json` 생성
3. **마스터 반영**: 신규는 `create_records_for_table`(45건 배치, typecast) — 응답 순서로 record id 확보 가능. 기존은 `update_records_for_table` (id 지정).
4. **마스터 재조회** 후 `master_map.json`(사업자번호→record id, 코드→record id) 생성, `python3 scripts/transform.py --phase2 ...` 로 소스/연락처/접속정보 payload 생성 (스크립트 상단 주석 참조).
5. **소스·연락처·접속정보 반영**: 대량이면 general-purpose 서브에이전트에 위임 (배치 45건, typecast true).
6. **검증·보고**: 단계별 건수, 신규 코드 범위, 해임일자/폐업일 목록, 접속정보 계정ID 충돌 목록, 택스봇에 없는 기존 마스터를 보고한다. **삭제·상태 임의 변경은 하지 않는다.**

## 변환 규칙 (2026-07 최초 동기화 기준)

- **행 병합**: 사업자번호 중복 행은 공동대표(대표자명만 다름) — 대표자명을 `, `로 합치고 나머지는 빈 필드 보충 방식으로 1행으로 병합
- **테스트 행 제외**: 상호 `test` / 사업자번호 `111-22-33333` 행은 마스터 생성 제외 (소스 테이블에는 원본 보존)
- **개인 고객(사업자번호 공란)**: 신고대리 개인. 마스터 생성 시 상호=대표자명, 메모에 "사업자번호 없음" 표기. 소스 테이블에는 upsert가 아닌 create (빈 병합 키 금지)
- **신규/기존 판정**: 사업자번호 기준. 신규는 기존 최대 코드 다음부터 `ST-####` 부여
- **기존 마스터**: `소스`에 "택스봇" 추가(기존 태그 보존 위해 조회값과 병합), 그 외 필드는 **비어있을 때만** 채움 (위멤버스 값 우선). 상호·거래처코드는 절대 갱신하지 않는다
- **신규 마스터**: 전체 필드 + 새 코드 + 소스 ["택스봇"]. 해임일자 있으면 상태=해지, 그 외 수임중. 폐업일/신고대리/대상제외/담당자지정필요는 메모에 `[택스봇] ...`으로 기록
- **담당자**: 실명(이동희·이태우·류재상·이준호)만 마스터 담당자에 기록. "대상제외"/"담당자지정필요"는 메모로만
- **전화·이메일**: 수임처등록정보의 휴대전화번호는 마스킹(뒤 4자리 ****)이므로 마스터 연락처는 **연락처정보 파일의 실번호**를 사용 (대표자명=성명 일치 우선). 소스_택스봇 테이블에는 마스킹 원본 그대로
- **연락처 파일의 빈 사업자번호 행**: `contacts_by_biz['']`로 다른 개인 고객에 오매칭되지 않도록 주의 — 반드시 이름 매칭만 사용
- **연락처 항목명**: `성명 — 상호`, 동일 키 중복 시 ` (2)` 등 부여. 완전 중복 행(성명·상호·사업자번호·핸드폰·구분 동일)은 제거
- **접속정보**: 홈택스ID 있는 거래처만. 항목명은 `홈택스 — {마스터 상호}` (위멤버스가 만든 기존 항목과 매칭되도록 마스터 상호 사용). 기존 항목의 계정ID가 택스봇과 다르면 **덮어쓰지 말고 충돌 보고**. 같거나 비어있으면 갱신. 홈택스2차인증번호는 메모에
- 회계시작일/종료일은 `0101` 같은 MMDD 텍스트 — date가 아닌 singleLineText
- 빈 문자열 필드는 payload에서 제거 (email/phone/date 타입 오류 방지)

## 주의

- 소스_택스봇 upsert에서 "multiple matches" 오류가 나면 병합 키(사업자번호) 중복 — 해당 건 보고 후 건너뛴다
- 동기화 후 마스터 총 레코드 수가 (기존 + 신규)와 다르면 링크 typecast가 새 마스터를 만든 것이므로 즉시 확인
- 거래처 링크는 이름 typecast가 아닌 **record id 배열**로 넣는다 (동명 거래처 존재: 육달×2, 태린건축×2 등)
