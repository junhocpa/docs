# YMK 일일시재 작성·검증 (지침 v1.0)

YMK의 자금 담당 업무: 영업일마다 일일시재 워크북에 당일 시트를 만들어 더존 ERP 분개장의 입출금을 반영하고, 검증 후 팀 메신저에 보고한다. 이 스킬은 그 전 과정(작성 → 검증 → 실잔고 대조 → 보고 메시지)을 표준화한다.

세부 구조·매핑·템플릿은 `references/`를 필요할 때 읽는다:

- `references/sheet-structure.md` — 시재 시트 구조(행·계좌 매핑, 수식 체계, MEMO 작성 관례, 작업가이드 원칙)
- `references/journal-and-verification.md` — ACA0050 분개장 읽기·계정/거래처 매핑·집계, 검증 체크리스트 전체, 실잔고 대조 원칙
- `references/messages.md` — 메신저 보고문·고객 안내문 템플릿

---

## 입력 파일 식별

업로드 파일명의 한글은 깨져 `______26____.xlsx` 형태가 되므로 내용으로 식별한다:

| 파일 | 식별 방법 | 용도 |
|---|---|---|
| 일일시재 워크북 | 시트명이 `YYMMDD`(예: 260731) 날짜들 + `작업가이드 시트`, `검증` | 작성/검증 대상 |
| 분개장 | `ACA0050Grid_excel_*.xlsx`, 1행 헤더 `승인일/승인번호/차변금액...` (91열) | 당일 거래 원천 |
| 자금일보 | `dzeditor_content_*.html` (더존 게시물) | ERP 총계 대조 |
| 은행 잔고조회 | 우리銀 전계좌조회/외화계좌조회 xlsx, 하나銀 계좌목록 xls | 실잔고 대조 |
| 삼성증권 잔고 | PDF (계좌별 평가·외화예수금) | 실잔고 대조 |

**주의**: ACA0050 파일은 openpyxl로 열면 스타일 버그(`CellStyle ... 'count'`)로 실패한다. 반드시 `pd.read_excel(..., engine='calamine', header=None, skiprows=1)`로 읽는다(`pip install python-calamine`).

## 업무 유형 4가지

요청을 다음 중 하나로 판별해 진행한다. 어느 경우든 **기존 수식은 절대 변형하지 않는다**(작업가이드 시트의 대원칙).

### A. 신규 일자 시재 작성 ("YYMMDD 시재 만들어줘")

1. 분개장에서 해당 승인일의 시재 계좌 관련 라인 전부 추출 (`references/journal-and-verification.md`의 계정·거래처 매핑).
2. 당일 시트(전일 시트 복사본)에 입금(H)/출금(I) 입력. 최신 구조에서는 H/I가 MEMO 금액 셀을 참조(`=+E55` 등)하므로 **MEMO를 먼저 작성**하고 H/I 참조를 연결한다.
3. 외화 거래가 있으면 K열(외화잔액)을 증감 반영해 갱신한다. 전액 매도·해지된 계좌는 K=0 (M열 #DIV/0! 표시는 잔액 0 계좌의 정상 관례).
4. MEMO 작성 (`references/sheet-structure.md`의 블록 관례).
5. 검증(아래 C) 후 결과 보고.

**파일 수정 원칙**: 워크북 전체를 openpyxl로 재저장하면 105+개 시트의 수식 캐시가 전부 소실된다. 가능하면 원본 zip에서 해당 시트 XML만 교체(다른 시트 바이트 동일 보장)하거나, openpyxl 저장 후 LibreOffice 재계산(`recalc.py`)으로 캐시를 복원한다. LibreOffice가 스프레드시트를 못 열면 `apt-get install -y --no-install-recommends libreoffice-calc` (컨테이너에 calc 모듈이 없는 경우가 있음).

### B. 사용자가 작성한 시재 검증 ("이거 맞는지 확인해줘")

`references/journal-and-verification.md`의 체크리스트 6단계를 전부 수행하고, 불일치는 **셀 주소·기대값·실제값**으로 특정해 보고한다. 숫자 검증 결과가 맞으면 명확히 "맞다"고 결론부터 말한다.

### C. 실잔고 대조 / 무거래 검증 ("거래 없었는지 확인해줘")

은행·증권 실제 잔고와 시재 최종 시트를 계좌별 대조한다. 핵심 원칙:
- **예금성 계좌**(보통예금·MMDA·MMF 좌수·예수금)는 정확히 일치해야 한다.
- **투자자산**(주식·채권·신탁·MMF 평가액·퇴직연금 평가액)은 기중 평가하지 않으므로 장부가와 시가 차이가 정상이다. 차이를 "문제"로 보고하지 않는다.
- 은행 조회의 **최종거래일**로 거래 발생일을 특정한다 — 잔고 차이가 있어도 최종거래일이 검증 대상일이 아니면 그날 거래가 아니다(예: 조회일 아침의 이자 입금).
- 시재 관리 대상에 없는 계좌가 잔고 자료에 보이면 확인 요청 사항으로 별도 보고한다.

### D. 보고 메시지 작성 ("메신저 내용 정리해줘", "고객 안내문처럼")

`references/messages.md`의 템플릿을 따른다. **메신저용 메시지는 반드시 코드블럭 안에 순수 텍스트로**(굵은 글씨·마크다운 서식 금지 — CLAUDE.md 응답 규칙과 동일).

## 핵심 규칙 (요약)

1. **수식 불변** — 기존 시트에 걸린 수식은 그대로. 값만 입력한다.
2. **이월 정확성** — 새 시트의 전일잔액(G)은 전일 시트의 잔액(J)을 하드코딩. **전액매도로 0이 된 계좌·신설 행을 놓치기 쉽다**(실사례: J리츠 Wrap 전액매도 다음 영업일에 G에 매도 전 80.3억이 남아 총액 과대계상).
3. **검산 L6=0** — 시트 자체 검산식 `(G6+H6-I6)-J6`이 0이어야 한다. 단 L6=0은 내부 정합만 보장하므로 이월·분개장 대사는 별도로 한다.
4. **분개장이 원천** — H/I 금액은 당일 승인 전표의 (계정과목, 거래처)별 차변=입금/대변=출금 집계와 정확히 일치해야 한다. 분개장이 재출력되면(환율 정정 등) 최신본 기준으로 재대사한다.
5. **자금일보 대조** — ERP 자금일보의 당일말시재액 + 퇴직연금 = 시재 J6. ERP는 삼성증권 예탁계좌 외화보통예금을 통합 표시하므로 시트의 USD/JPY/원화 분리 행을 합산해 비교한다.
6. **투자자산 기중 미평가** — 실잔고 대조에서 평가액 차이는 정상. 결산(분기말 기말평가반영 시트)에서만 반영된다.
7. **다른 시트 불가침** — 작업 대상 일자 외 시트는 값 하나도 바뀌면 안 된다(시트별 해시 비교로 확인).

## 흔한 함정

- **ACA0050를 openpyxl로 열기** → calamine 엔진 사용 (위 참조).
- **워크북 통재저장으로 수식 캐시 소실** → 시트 XML만 교체 또는 재계산 필수.
- **전액매도 계좌의 이월 누락** → 이월 대조는 "값 있는 행"만이 아니라 전 계좌 행에 대해 전일 J와 비교.
- **K열(외화잔액) 갱신 누락** → 외화 거래일에는 K를 외화 증감으로 재계산. 작업가이드의 "K열 이후 금지"는 시트 복사 단계의 지침이며 거래 반영 시에는 갱신하는 것이 기존 관례.
- **원화 소액(예: 원화잔액이체 4원)의 귀속** — 시재에 해당 원화 행이 없으면 행 신설이 정석(실사례: 18행 삼성증권 예탁계좌 원화 행 신설). 외화 블록에 원화를 끼워 넣으면 M열 환산단가가 왜곡된다.
- **MMF 매도 금액 구분** — MMF 행 출금은 장부가(원금), 입금 계좌에는 원금+이자−원천세(선납세금 14% + 지방소득세 10%)가 들어간다. 메모에는 `우리큰만족법인매도 KRW <원금>` 관례.
- **분개장 재출력본 확인** — 같은 날 분개장이 여러 번 출력되면 라인 수·차대합이 같아도 개별 금액(환율)이 다를 수 있다. 시간이 늦은 파일이 최신.
- **오류 캐시의 원죄 구분** — M열 #DIV/0!(잔액 0 외화 계좌), O열 #REF!, 기말평가 시트 B4 #VALUE!는 원본에 원래 있는 것. 새로 만든 오류와 혼동하지 말 것.
