## 회계처리 분류 체계 (내역구분)

| 회계처리구분 | 세부유형 | 적용 조건 | 분개 형태 | NO 매핑 |
|---|---|---|---|---|
| 타계정대체 | **전기대체** | 재고일자 < 당기시작 + 출고후 원재료 | 원재료/PJT 1번(출고전 강제) → 출고후 PJT/원재료 | 차변=7, 대변=8 |
| 타계정대체 | **상품대체** | 출고후 = 상품 (원재료 → 상품) | 차변 상품(1460000) / 대변 원재료 | 차변=5, 대변=8 |
| 타계정대체 | **연구개발비대체** | 출고후 = 연구개발(PJT `999999`·`990904` 등) | 차변 경상연구개발비(제조 `523`)+PJT `93` / 대변 원재료 — 규칙 10 | 차변=3, 대변=8 |
| 타계정대체 | **원재료대체** | 당기재고 + 원재료↔원자재 변환 | 차변 원재료 / 대변 원재료 (PJT만 다름) | 차변=7, 대변=8 |
| **타프로젝트대체** | - | 재고일자 ≥ 당기 + 계정 동일 + PJT만 다름 | 양쪽 차변(+/-) / 타계정구분 X | 양쪽 5/7/3 |

차대구분(더존 I컬럼)은 `3`=차변, `4`=대변. 위 NO 매핑은 내역구분 참고값이다.

## 규칙 1. 의미있는 데이터 필터링
ERP 출고현황에서 다음만 추출:
1. 구분 = `일반` (미일반은 전량 제외)
2. 출고일자 = 전월 1일 ~ 말일
3. 재고금액 ≠ 0원
4. 출고전·후 [PJT + 계정]이 모두 같고 재고일자가 당기인 행은 **제외**. 단, 계정변환·전기재고는 무조건 포함.

## 규칙 2. 전기재고 처리
재고일자가 전기(당기시작일 이전, 예: 2026-04-01 이전)이면 출고전을 강제 변환:
- 계정과목 → 원재료(`1490000`)
- PJT 코드 → `000001` (장비공통)

사유: 기말마감 시 전기 잔여재고가 모두 [원재료/PJT 1번]으로 일괄 처리되었기 때문.

## 규칙 3. 분개 통합 (★ v1.1 정정)
**변환 후 최종 전표 라인** 기준으로 `[작성일자(출고일자) + 계정 + 거래처 + 프로젝트 + 차대구분]`이 같으면 **1개 라인으로 합산**. 하나라도 다르면 별도 유지.

★ 통합 키 적용 시점: 규칙 2(전기재고→원재료/PJT1)·규칙 4(26기→000092)·규칙 5(상품 공란) 등 **모든 변환을 거친 뒤**의 최종 라인 값으로 판단한다. 따라서 원본 출고전/출고후 PJT가 서로 달라도, 변환 후 라인의 [일자·계정·거래처·PJT]가 같아지면 합산한다.

예(2026-05 에이엔티): 출고후 PJT가 `8004`(9,590)·`60205`(68,283)로 달랐으나, 둘 다 출고후=상품(공란)/출고전=전기재고(원재료·PJT `000001`)로 변환 → 최종 키 동일 → 차변 상품 77,873 1라인 + 대변 원재료 77,873 1라인으로 통합. 통합 원본은 ⑤분개검토표 적요·변환/특이 칸에 "N건 통합" 표기.

## 규칙 4. 26기 PJT → [92.전기프로젝트] 자동 변환
- 사유: 26기 PJT는 [미사용] 처리되어 27기 조회 안 됨. 적용은 2026년 4월(27기)부터.
- PJT 코드 → `000092`, PJT명 → `전기프로젝트`
- 적요 끝에 `| 원PJT PJT071010(IT #6,7 부착기)` 형태로 원본 PJT 자동 추가.
- 회계연도 변경 시(예: 28기 시작) "당시의 전기 PJT → 92" 로직 동일 적용. 27기가 전기가 되면 27기→92 변환 추가.

## 규칙 5. 상품(1460000) 계정 라인 - PJT/부서 공란
상품 계정 라인은 아래 3개 컬럼 모두 공란: 프로젝트/부서코드(D), 사용부서(M), 프로젝트(N). 사유: 상품 계정은 PJT/부서 관리 대상 아님.

## 규칙 6. 품의내역 단순화
품의내역(O컬럼)은 `타계정대체` 또는 `타프로젝트대체` 둘 중 하나. (적요 컬럼은 종전대로 유지.)

## 규칙 7. 거래처 자동 매칭
거래처명을 거래처 마스터에서 검색해 회계 거래처코드(5자리 zero-pad) 적용. 마스터가 없으면 분개장에서 거래처명→코드 확인. 특이사항 자동 검출:
- 동일거래처명 미사용코드 존재 → 사용중 코드만 적용
- 사업번호 더미값(`1111111111` 등) → 해외/특수거래처 표시
- 해외거래처(일본·미국·중국) → 통화/환율 별도 확인. 재고금액에 소수점이 있으면 환산 여부 확인.

## 규칙 8. 적요 표준 문구 (★ v1.3 개정 — 선례 형식으로 통일)
타계정대체: 차변 `타계정에서 대체액` / 대변 `타계정으로 대체액` (92변환 시 각각 `| 원PJT ...` 추가).
타프로젝트대체: 증가(+) 라인 `타프로젝트에서 대체액` / 감소(-) 라인 `타프로젝트로 대체액`.

★ 종전 v1.2의 `타프로젝트로 대체(+)/(-)` 표기는 폐기. 실제 전표 선례(2026-01-08 #4, 2026-07-05 입력분)와 동일한 형식을 쓴다 — 전표복사 시 적요 수정이 불필요해진다.

## 규칙 9. 전표복사 참조 기재 (★ v1.2 신설)
더존 입력 시 **전표 복사** 기능으로 과거 동일 유형 전표를 불러와 금액·PJT만 수정하므로, 각 전표에 분개장에서 조회한 **가장 최근 유사 전표의 [승인일자 + 승인번호]**를 참조로 기재한다.
- 유사 판단: 같은 회계처리 유형(상품대체/원재료 타계정대체/전기대체/연구개발비대체 등). 전표번호는 더존에서 **일자별 재시작**이므로, 일자만이 아니라 계정·유형까지 같은 최근 전표를 찾는다. 같은 유형의 최근 전표가 여럿이면 **거래처·PJT까지 같은 전표를 우선**한다(복사 후 금액만 수정하면 되도록).
- 출처: 분개장에서 적요 `대체액` 포함 + 차변계정(상품 `1460000`/원재료 `1490000`) 필터 → 전표 단위(승인일+승인번호) 그룹 → 가장 최근 1건.
- 기재 위치: ②자동전표업로드 시트 우측 보조컬럼 **T(참조일)/U(참조번호)/V(유형)** — ★ 더존 업로드 제외, A~S열만 업로드. ⑤분개검토표·①요약 시트에는 `YYYY-MM-DD #번호 (유형)` 형식.

예(2026-05): 상품대체(5/15) → `2026-04-22 #12` / 원재료 전기대체(5/26) → `2026-04-17 #5`.
예(2026-07): 상품대체(7/6·14·22) → `2026-06-09 #8` / 원재료 전기대체(7/8) → `2026-06-16 #6·#7`(거래처·PJT 동일 전표 우선) / 타프로젝트대체(7/5) → `2026-01-08 #4`.

## 규칙 10. 연구개발비 대체는 제조경비(523)/PJT 93 (★ v1.3 신설 — 고객 요청)
기존 재고가 **연구개발 프로젝트(`999999`, `990904` 등)로 사용**되는 타계정대체는:
- 차변 계정: 판관비 연구개발비가 아닌 **제조경비 경상연구개발비 `523` 계열**(7자리 코드는 더존 계정과목 조회로 확인, `5230000` 추정)
- 관리항목 프로젝트: **`93.연구개발`(000093)** 입력
- 대변: 원재료(1490000) — 통상 규칙과 동일. 사용부서는 기존 관행(2000) 유지하되 발생 시 확인.
- 근거: 2026-06-02 YMK 박수진님 요청(결산 과정에서 수정된 사항). 2026-05월분부터 적용, **이전 건 소급수정 없음**.

## 규칙 11. 타계정구분 지정 + 사후검증 (★ v1.3 신설)
타계정구분은 더존 전표입력 화면의 관리항목으로, **19컬럼 업로드 양식에 없다** → 입력 후 반드시 별도 확인한다.
- 타계정대체: 차변 라인 `1.타계정대체입고` / 대변 라인 `2.타계정대체출고`
- 타프로젝트대체: 지정 안 함(공란)
- ★ 전표복사 후 **새로 추가한 라인**은 타계정구분이 빠진 채 저장되기 쉽다(2026-07-08 요도가와 640770 차변 라인 사례 — 복사된 2라인은 정상, 추가 라인만 누락). 입력 완료 후 계정별 상세원장에서 대체 라인의 타계정구분을 전수 확인하고, 누락 라인은 전표 수정으로 지정한다. 제조원가명세서·주석의 타계정대체 집계에 영향.
