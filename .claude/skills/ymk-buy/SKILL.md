# YMK 매입세금계산서 전표 미발행 검토·대사 (지침 v1.0)

매월(또는 부가세 신고 전) 더존에 전표 입력이 안 된 매입세금계산서를 찾아, 기존 분개장 패턴대로 전표 처리안을 만들고 구매시스템 입고자료와 원단위까지 대사하는 표준 절차다. **원칙: 데이터로 확인되는 것만 제안하고, 확인 안 되는 것은 "확인 불가"로 명시한다(추정 금지).**

세부 규칙·마스터는 `references/`를 필요할 때 읽는다:

- `references/voucher-patterns.md` — 계정과목·거래처·PJ 마스터, 거래처 유형별 분개 패턴, 공과금 거래처, 상쇄쌍 판정 (반드시 처리 전에 정독)
- `references/recon-and-output.md` — 입력 파일별 스키마·읽기 팁, 대사 절차, 산출 워크북 시트 구조, 메신저 보고 양식
- `scripts/load_helpers.py` — 더존/구매시스템 엑셀 로더 + PJ 정규화 + 미발행 추출 헬퍼

---

## 트리거와 입력

**필수 입력**
- ACB2050 세금계산서 리스트(`acb2050_taxData_...xlsx`) — 컬럼에 `전표여부`(전표발행/전표입력/미발행) 포함.
- ACA0050 분개장(`ACA0050Grid_...xlsx`) — 거래처별 기존 전표 패턴 조회용.

**보조 입력(있으면 대사까지, 없으면 패턴 제안까지만)**
- 자재진행리스트 — 품목 단위 발주/입고 + PJT코드 + TAX발행일 (원재료 PJ 분리 근거).
- 입고등록마스타 — 입고번호 단위 + PJT코드 + TAX발행일 (원재료 대사 확정치).
- 입고현황 — **상품** 입고(PJT코드 없음).
- ACB2050 대조 차이 파일(`acb2050_diff_...`) — 홈택스-더존 차이 현황 보고용.

더존 export는 openpyxl이 스타일 오류로 실패할 수 있다 → **pandas `engine="calamine"`** 사용. 하단 '합계' 행 제거. 상세는 `references/recon-and-output.md`.

## 작업 STEP 7단계

1. **미발행 추출** — 구분=`매입` & 전표여부=`미발행` 필터. 매출 미발행은 범위 외지만 발견 사항은 참고로 보고.

2. **3분류** — 미발행 건을 나눈다:
   - **(A) 신규 입력 필요**: 월말 정기 매입 등 실거래. → STEP 3~5로 처리안 작성.
   - **(B) 상쇄 수정쌍**: 같은 거래처·같은 작성일에 ±동액 쌍으로 순액 0. → 분개장에서 **원본 거래의 전표 처리 여부를 확인**한 뒤 "전표 불필요(부가세 합계표 반영만 확인)"로 보고. 순액이 0이 아닌 쌍(예: 감액 정정)은 잔여 순액의 전표 반영 여부를 반드시 추적.
   - **(C) 기간외/공과금**: 작성일이 오래된 건(누락 의심), 통신·공과금 거래처(국세청 전송 지연 관행). → 별도 플래그.

3. **분개장 패턴 조회** — (A)의 각 거래처에 대해 분개장에서 전표키(`작성일+작성번호`)로 묶어 최근 매입전표 2~3건의 라인 구조를 본다: 차변 계정(+PJ/사용부서), 부가세대급금, 대변 계정, 품의내역, 적요 형식. 거래처명·코드는 **분개장(ERP) 명칭**을 제안한다(세금계산서 상호와 다를 수 있음). 이력이 전혀 없는 거래처는 **확인 불가**로 표기하고 품목 확인을 요청한다.

4. **입고자료 대사 (보조 입력 있을 때)** — 매칭 키는 `거래처명(부분일치) + TAX발행일(=세금계산서 작성일) + 금액`. 원재료는 자재진행리스트(매입원가)·입고등록마스타(합계금액) 양쪽으로, 상품은 입고현황으로 대사한다. **차이 0을 확인**하고, 발주액과 다르면 미입고분을 원인으로 규명한다(입고 기준이 세금계산서와 일치하는지). PJT코드는 선행 0 소실 주의(5자리면 앞에 0 부착: `21101→021101`, `71017→071017`; `71`은 그대로).

5. **전표 처리안 확정** — 거래처별로 전표 라인을 만든다:
   - 원재료(1490000) 라인을 **PJ별로 분리**(상품은 PJ 분리 제외, 990909는 경상연구개발비(5230000)로).
   - 부가세대급금(1350000) = 세액, 대변 = 재고성이면 외상매입금(2510000), 경비성이면 미지급금(2530000).
   - 품의내역·적요는 기존 패턴 그대로(`원재료매입`/`상품매입`/`부품대[PJ코드]` 등, `references/voucher-patterns.md`).
   - **각 전표 차변합=대변합, 원재료 소계=세금계산서 공급가액**을 코드로 검증한다.

6. **검토 워크북 산출** — 시트: ①전표입력필요(요약+대사결과) ②전표라인(PJ분리) ③기간외/누락 ④전표불필요(상쇄쌍) ⑤참고(매출). 구조는 `references/recon-and-output.md`. 합계는 검증된 값으로 기입(원격 환경에서 LibreOffice recalc가 자주 실패하므로 수식 의존 금지).

7. **메신저 보고** — 요청 시 고객사(YMK 담당자) 보고문을 **코드블럭 안 순수 텍스트**(굵은 글씨 등 마크다운 서식 금지)로 작성. 양식: "전자 세금계산서 매출/매입" 섹션 + 불릿. 공과금 거래처는 "기존과 같이 국세청 전송 지연" 문구, 미확인 건은 확인 요청. 간략 버전 요청 시 당월 외 건은 제외.

## 검증·보고 원칙

- 모든 금액 대조는 **원단위**로. "대략 일치"는 없다 — 차이가 나면 원인(미입고·상쇄쌍·전송지연)을 규명해 적는다.
- 대형·이례 금액(평소 월 매입의 수 배)은 일치해도 명세 확인 필요로 플래그.
- 검토 중 발견한 부수 이슈(과거 누락, 매출 순액 미상쇄 등)는 범위 외라도 반드시 보고에 포함.
- 이미 종결된 판단을 재검토할 때는 새 차이 파일(최신 대조 결과)로 현재 상태를 재확인 후 보고한다.
