# 입력 스키마·대사 절차·산출 양식

## 1. 입력 파일별 스키마·읽기 팁

공통: 더존/구매시스템 export는 openpyxl이 스타일 파싱 오류(`CellStyle... 'count'`)로 실패할 수 있다 → `pd.read_excel(path, engine="calamine")`. 거래처코드·사업자번호·계정과목코드는 `dtype=str`. 하단 `합계` 행 제거.

### ACB2050 세금계산서 리스트 (`acb2050_taxData_...`)
헤더 1행. 컬럼: No, 구분(매입/매출), 분류(일반/수정), 작성일, 발급일, 전송일, 거래처코드, 거래처명, 사업자(주민)번호, 공급가액, 세액, 합계금액, …, **전표여부**(전표발행/전표입력/미발행), 전표정보(예 `20260704-00001`), 거래처대표자명.
- 미발행 추출: `구분=='매입' & 전표여부=='미발행'`.
- 수정 건은 음수 금액 존재. 영세율은 세액 NaN.

### ACA0050 분개장 (`ACA0050Grid_...`)
헤더 1행, 91컬럼. 핵심: 승인일, 승인번호, 차변금액, 차변계정과목(`[코드]명`), 대변계정과목, 대변금액, 적요, 거래처코드, 거래처명, 작성일, **작성번호**, 프로젝트코드/명, 사용부서명, 전표유형명(`매  입`/`매  출`/`일  반`—공백 2칸 주의), 증빙명, **품의내역**, 전표라인번호, 계정과목코드/명.
- **전표키 = `작성일 + '-' + 작성번호`** 로 라인을 전표 단위로 묶는다.
- 거래처 패턴 조회: 해당 거래처의 매입유형 전표 최근 2~3건의 라인 구조·품의·적요를 본다.
- "이미 입력됐는지" 확인: 해당 작성월에 같은 거래처 매입전표 존재 여부 + 금액 검색.

### 자재진행리스트 (구매시스템, 품목 단위)
헤더 2행째(`header=1`). 핵심: PJT코드, PJT명, 발주일자, 품명, 규격, 수량, 단가, **공급가액**(발주), 거래처, 입고일자, **매입원가**(입고), 발주번호, **TAX발행일**.
- 대사 금액은 **매입원가**(입고 기준). 발주 공급가액과 다르면 미입고 차이.

### 입고등록마스타 (입고번호 단위)
`header=1`. 핵심: PJT코드, 입고번호, 입고일자, **거래처**, 외화금액, **합계금액**, **TAX발행일**. 원재료 대사 확정치.

### 입고현황 (상품, PJT코드 없음)
`header=1`. 핵심: 입고번호, 입고일자, **입고처**, **기본입고금액**, **TAX발행일**. 상품 매입 대사용.

### ACB2050 대조 차이 파일 (`acb2050_diff_...`)
헤더 2행(그룹 헤더) → `header=None`으로 읽고 수동 파싱. 거래처 요약행(거래처명 있음)과 일자별 상세행 반복. 컬럼 블록: 전표자료(매수/일자/공급가액/세액/합계) | 국세청자료(동일) | 차이(매수/공급가액/세액).
- **전표에만 있음(+)** = 국세청 미전송(공과금 관행) / **국세청에만 있음(−)** = 전표 미입력.
- 마지막 상세행은 총계. 차이 총액 = 개별 차이 합으로 검산.

## 2. 대사 절차

1. 매칭 키: `거래처명 부분일치 + TAX발행일(=세금계산서 작성일)`. 거래처명은 파일마다 표기가 다르다(（주）/㈜/주식회사/생략) — 핵심 상호로 contains 매칭.
2. 원재료: 자재진행리스트(매입원가)와 입고등록마스타(합계금액) **양쪽에서** PJ별 합계를 내고 서로 일치 + 세금계산서 공급가액과 차이 0 확인.
3. 상품: 입고현황 합계로 대사. 상품은 PJ 분리하지 않는다.
4. PJ 정규화(선행 0)와 990909→경상연구개발비, 71→원재료[조립품] 매핑은 `voucher-patterns.md` §2.
5. 불일치 시: 미입고(발주-입고 차이), 분할 발행, 상쇄쌍, 전송 지연 순으로 원인 후보 점검. 원인 미상이면 확인 불가로 보고.

## 3. 산출 워크북 (`YMK_매입세금계산서_전표미발행_검토_YYYYMM.xlsx`)

폰트 맑은 고딕 9pt, 헤더 회색(D9E1F2)+볼드, 테두리, 숫자 `#,##0`. 확인불가·경고는 노란 채움(FFF2CC), 대사 일치는 연녹색(E2EFDA). **합계는 파이썬으로 검증한 값**을 기입(원격 환경 LibreOffice recalc가 자주 실패 — 미계산 수식을 남기지 말 것).

| 시트 | 내용 |
|---|---|
| 1_전표입력필요(N월) | No·작성일·거래처코드/명(ERP)·공급가액·세액·합계·제안 계정(차변)·품의내역(안)·전표란/적요(안)·대사 결과 |
| 2_전표라인(PJ분리) | 거래처 블록별 실제 전표 라인: 차/대, 계정, PJT코드, 프로젝트명, 금액, 적요. 블록마다 소계(차변합=대변합) 검증 |
| 3_기간외/누락 | 당월 외 미발행(예: 전기분 공과금) — 제안 분개 + 결산·부가세 반영 확인사항 |
| 4_전표불필요(상쇄쌍) | ± 쌍 목록 + 근거(원본 전표번호·품의) + 부가세 합계표 확인 문구 |
| 5_참고(매출 미발행) | 범위 외 발견 사항. 순액 미상쇄 건은 경고 강조 |

전표라인 무결성 검증(필수): 블록별 차변합==대변합==소계, 원재료+연구개발비 소계==세금계산서 공급가액.

## 4. 메신저 보고 양식

CLAUDE.md 규칙: **코드블럭 안 순수 텍스트**, 굵은 글씨 등 마크다운 서식 금지. 기본 골격(기존 보고 관례):

```
안녕하세요 ○○님, N월분 홈택스-더존 세금계산서 대조 결과 공유드립니다.

전자 세금계산서 매출
- 국세청과 더존 자료 일치합니다. (예외가 있으면: 취소 후 재발행 +/-N매는 합계 0원으로 금액 차이 없습니다)

전자 세금계산서 매입
- 업로드해주신 상품, 자재리스트와 대사하여 미처리 N건 모두 금액 일치 확인 후 프로젝트별로 분리하여 전표처리 완료했습니다. (미입고 차이가 있으면 입고분 기준 처리 명시)
- 통신비, 공과금 거래처(...)는 기존과 같이 국세청 전송 지연에 따른 차이로, 전표는 모두 입력되어 있어 전송되면 일치합니다.
- 미확인 건(거래처, 일자, 금액)은 내역 확인 후 작성 부탁드립니다.
```

작성 요령: 완료 보고 → 정상 차이(공과금) → 요청사항 순. 간략 버전 요청 시 당월 외 항목·부연 설명 제거. 상대가 직접 처리하겠다고 한 건은 완료 대상에서 빼고 "말씀 주신 대로" 문구로 존중.
