# 솔루션택스 실행 전략 — 구조도·절차·단계별 액션플랜

> 2026-07-21 기준 · [업무 플랜 문서 세트](./README.md)의 실행 전략 편
> 핵심 논리: **자동화로 시간을 벌고 → 그 시간으로 성장 엔진(영업·신규 서비스)을 돌리고 → 늘어난 매출로 조직을 만든다**

## 1. 사업 구조도 — 6개 축이 맞물리는 방식

세 계층으로 본다. 기반이 튼튼해야 성장 축이 돌아가고, 성장의 결실이 다시 기반에 재투자된다.

```mermaid
flowchart TB
    subgraph G["🚀 성장 계층 (매출을 늘린다)"]
        S3["3. 영업·조직<br/>소개·제휴·업셀"]
        S4["4. 홈페이지<br/>유입·신뢰 채널"]
        S5["5. 신규 업무<br/>양도·증여·상속세"]
        S2["2. 아웃소싱<br/>경리·급여·결산"]
    end
    subgraph O["⚙️ 운영 계층 (매출을 지킨다)"]
        S6["6. 기타 업무<br/>신고 사이클·기한 준수"]
        CS["기존 기장 153곳<br/>월 기장료 수입"]
    end
    subgraph F["🏗️ 기반 계층 (시간을 만든다)"]
        S1["1. 내부시스템<br/>Airtable DB·CMS 수금<br/>자동화 스킬·매뉴얼"]
    end
    S1 -->|"기한·수금·정보 관리"| O
    S1 -->|"절감된 시간 투입"| G
    O -->|"안정적 현금흐름"| G
    G -->|"신규 수임·건당 수수료"| CS
    G -->|"매출 증가 → 채용·성과급 재원"| S1
```

**전략적 함의**
- 8월에 기반(1번 축)을 먼저 완성하는 이유: 이후 모든 축이 이 위에서 돌아간다. *(Airtable 구축은 7/21 조기 완료됨)*
- 아웃소싱(2)은 성장 축이면서 이미 운영 중(YMK) — 가장 빨리 매출화 가능한 축이므로 9월에 상품화한다.
- 홈페이지(4)는 단독 목표가 아니라 영업(3)·신규 업무(5)의 **수주 창구**다. 콘텐츠도 서비스 소개가 중심.

## 2. 시스템·데이터 구조도 — 정보가 흐르는 길

```mermaid
flowchart LR
    subgraph SRC["원천 소스 (별도 페이지 보존)"]
        W["위멤버스 ✅153"]
        C["CMS"]
        CH["채널톡"]
        K["카카오톡"]
        N["내부관리"]
        T["택스봇"]
    end
    subgraph AT["Airtable 솔루션택스 업무관리"]
        M["거래처 마스터<br/>ST-0001~0153<br/>코드로 통합"]
        SCH["신고일정"]
        FEE["수수료·수금"]
        ACC["접속정보<br/>계정·비밀번호 ✅156"]
        TSK["업무태스크"]
    end
    subgraph OUT["업무 실행"]
        RPT["신고·기장 실무"]
        CMS2["CMS 자동 수금"]
        PAY["담당자별 매출 집계<br/>→ 성과급 산정"]
        KPI["월말 KPI 리뷰<br/>→ 대시보드"]
    end
    SRC -->|"파일 업로드 시 스킬로<br/>upsert 동기화"| M
    M --> SCH --> RPT
    M --> FEE --> CMS2
    FEE --> PAY
    M --> ACC --> RPT
    M --> TSK
    FEE --> KPI
    SCH --> KPI
```

**운영 원칙**
- **소스는 보존, 마스터가 기준**: 소스 테이블은 원본 그대로, 판단·업무는 항상 마스터(거래처코드) 기준
- **재업로드 = 동기화**: 위멤버스 파일은 `wemembers-sync` 스킬로 자동 upsert (신규 코드 부여·변경 반영·해지 후보 감지). 다른 소스도 같은 패턴으로 확장
- **문서와 데이터의 분리**: 데이터는 Airtable, 매뉴얼·플랜·스킬은 docs 저장소(git)

## 3. 핵심 절차 플로우

### 3-1. 월간 운영 사이클 (모든 달의 뼈대)

```mermaid
flowchart LR
    A["1~5일<br/>자료 수취<br/>증빙·급여 마감"] --> B["10일<br/>원천세<br/>신고·납부"]
    B --> C["10~15일<br/>전표 입력<br/>4대보험 처리"]
    C --> D["15~20일<br/>월 마감 검토<br/>계정 대사"]
    D --> E["25일<br/>CMS 출금<br/>결과 기록"]
    E --> F["말일<br/>지급명세서 제출<br/>세금계산서 마감<br/>월말 리뷰 30분"]
    F -->|"다음 달"| A
```

- 독촉 규칙: 5일 1차 요청 → 10일 2차(마감 영향 안내) → 15일 유선
- 구축성 작업(시스템·영업·홈페이지)은 **10일 이후~월말 전** 구간에만 배치

### 3-2. 신규 수임 프로세스 (영업 → 온보딩)

```mermaid
flowchart LR
    L["리드 발생<br/>소개·제휴·홈페이지"] --> A["① 상담<br/>상담 시트 작성"]
    A --> B["② 견적<br/>요금 기준표 적용<br/>재량 할인 금지"]
    B --> C["③ 계약<br/>수임계약서<br/>+CMS 출금동의<br/>+개인정보 동의"]
    C --> D["④ 온보딩<br/>홈택스 수임동의<br/>자료 인수<br/>Airtable 등록"]
    D --> E["첫 달 기장<br/>병행 검증 후<br/>정상 사이클 편입"]
    B -.->|"보류 리드"| F["리드 관리<br/>분기 재접촉"]
```

- 각 단계 양식(상담 시트·요금표·계약서·온보딩 체크리스트)은 8월에 `templates/`로 완성 → 이후 누가 해도 같은 품질
- 온보딩 완료 조건: Airtable 거래처코드 부여 + 접속정보 등록 + 신고일정 등록 3종 세트

### 3-3. 재산제세 서비스 플로우 (신규 업무)

```mermaid
flowchart LR
    Q["문의<br/>기장고객·중개 제휴·홈페이지"] --> A["유료 상담<br/>사실관계 확인<br/>개략 세액 안내"]
    A --> B["정밀 계산<br/>체크리스트 기반<br/>시나리오 비교"]
    B --> C["신고 대리 수임<br/>착수금 50%"]
    C --> D["신고서 제출<br/>납부 안내·잔금"]
    D --> E["사후 관리<br/>경정 대응<br/>기장 수임 연결"]
    A -.->|"상담만 종료"| Z["상담료 수취<br/>리드 보관"]
```

- 기한 관리: 수임 즉시 Airtable 신고일정 등록 (양도 2개월 / 증여 3개월 / 상속 6개월 — 속한 달 말일 기산)
- 전략 포인트: 기장 고객 153곳의 **대표자 개인 자산 이슈**가 1차 시장 — 대표자정보 DB(156명)가 이미 있음

## 4. 단계별 실행 전략 (Phase)

```mermaid
flowchart LR
    P0["Phase 0 ✅<br/>7월: DB 구축<br/>(조기 완료)"] --> P1["Phase 1<br/>8월: 기반 완성<br/>수금·양식·정보"]
    P1 --> P2["Phase 2<br/>9월: 표준화·상품화<br/>매뉴얼·요금·콘텐츠"]
    P2 --> P3["Phase 3<br/>10월: 성장 가동<br/>오픈·제안·수주"]
    P3 --> P4["Phase 4<br/>11월~: 시즌·확장<br/>연말정산·채용"]
```

| Phase | 기간 | 목표 (한 문장) | 핵심 액션 | 완료 기준 (DoD) |
|---|---|---|---|---|
| **0. DB 구축** ✅ | 7월 | 거래처 데이터를 한곳에 모은다 | Airtable 5+7테이블, 153곳 입력, 동기화 스킬 | ✅ 마스터 153·접속정보 156·스킬 커밋 |
| **1. 기반 완성** | 8월 | 수금과 정보 관리가 자동으로 돈다 | CMS 계약·동의 수취, 인증서 만료일 전수 입력, 수임 양식 4종, 중간예납 처리 | CMS 첫 출금 준비 완료 · 양식으로 신규 상담 1건 처리 가능 · 8/31 중간예납 전건 완료 |
| **2. 표준화·상품화** | 9월 | 팔 수 있는 상품과 시스템이 갖춰진다 | 월 마감 매뉴얼, 아웃소싱 요금표·계약서, 양도세 계산 시트, 홈페이지 원고, 기본급 조사 | 매뉴얼만 보고 제3자가 월 마감 가능 · 아웃소싱 견적 즉시 산출 가능 · 9/25 CMS 첫 출금 성공 |
| **3. 성장 가동** | 10월 | 성장 채널이 실제로 열린다 | 홈페이지 오픈, 아웃소싱 업셀 제안, 재산제세 상담 접수 개시, 성과급 산식 확정, 부가세 예정 | 홈페이지 경유 문의 동선 작동 · 업셀 제안 5건 발송 · 10/26 부가세 전건 완료 |
| **4. 시즌·확장** | 11월~ | 성수기를 조직으로 받아낸다 | 연말정산 준비, 종소세 중간예납(11/30), 채용 판단·공고, 11~1월 플랜 수립 | 연말정산 대상 집계 완료 · 채용 여부 의사결정 완료 |

## 5. 성장 플라이휠 — 이 전략이 돌아가는 원리

```mermaid
flowchart TB
    A["반복 업무 자동화<br/>(스킬·DB·CMS)"] --> B["회계사 시간 확보"]
    B --> C["영업·신규 서비스에<br/>시간 투입"]
    C --> D["수임 증가<br/>건당 수수료 매출"]
    D --> E["매출 성장"]
    E --> F["채용·성과급 재원"]
    F --> G["처리 용량 확대"]
    G --> A
    E -.->|"사례·레퍼런스"| C
```

병목이 항상 **회계사의 시간**이므로, 매 Phase에서 "이번 달 자동화·표준화로 몇 시간을 벌었고 어디에 썼는가"를 월말 리뷰에서 확인한다.
